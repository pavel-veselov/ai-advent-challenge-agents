# Changelog — File Assistant

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — по дням проекта.

## [1.1.0] — день 35 — агентный промпт нового поколения

### Changed

**Агентный системный промпт** (константа в `src/llm.js:56`)
- Цели принимаются только на уровне намерения («найди все места, где используется X», «обнови README из кода»), без пошаговых инструкций — ассистент сам планирует действия.
- Инициативный режим работы: сначала `search_files`/`read_file` по реальному содержимому, затем вывод или `write_file`; опора на факты из файлов вместо догадок.
- Финальный отчёт по строгому шаблону: списком `файл:строка` для находок и «файл + краткое описание диффа» для изменений, без сырых дампов вызовов инструментов.
- Правила джейла закреплены в промпте: пути только относительно корня рабочей области; запросы на запись вне проекта — вежливое отклонение.
- Язык ответа — язык пользователя (по умолчанию русский).

### Checked (E2E-сценарии)
- «найди все места, где используется функция chatWithTools» → `search_files` (+`read_file`) → ответ списком `файл:строка`.
- «сгенерируй файл file-assistant/CHANGELOG.md с кратким changelog этого ассистента» → `write_file` → `file_change` с диффом в UI, файл на диске (обновление 1.0.0 → 1.1.0 выполнено самим ассистентом).

## [1.0.0] — день 34 — первый релиз

AI-ассистент, который активно работает с файлами проекта: читает, ищет, анализирует и создаёт/меняет файлы через MCP-инструменты и tool-calling цикл LLM. Zero-deps: только Node 20+, без npm-пакетов и CDN.

### Added

**Ядро и LLM**
- HTTP-сервер на `node:http` (`server.js`): статика `public/` + API — `POST /api/ask` (NDJSON-стрим), `GET /api/status`, `GET /api/health`.
- Чат с локальной LLM GPUStack (модель по умолчанию `glm-5.3-flash`) через OpenAI-style `/v1/chat/completions` со SSE-стримингом (`src/llm.js`).
- Tool-calling цикл до 6 итераций: итерации с инструментами — не-стримингово, финальный ответ — стримом.
- Агентный системный промпт: цели на уровне намерения, «сначала поиск/чтение — потом вывод/запись», краткий отчёт в формате `файл:строка`, запись только внутри рабочей области.

**MCP-слой**
- stdio-клиент MCP (JSON-RPC 2.0, newline-delimited, `spawn`) — `src/mcp-client.js`; ленивый запуск, автоперезапуск после смерти процесса (сбой MCP не роняет запрос).
- stdio-сервер MCP с файловыми инструментами — `mcp/fs-server.js`:
  - `list_files` — рекурсивный список с glob-lite-фильтром (`*.md`, `src/*`), джанк-директории пропускаются, кап 500 записей;
  - `read_file` — до 400 строк / 48KB по умолчанию, `offset`/`limit`, метаданные диапазона строк;
  - `search_files` — поиск подстроки без учёта регистра, формат `путь:строка: фрагмент`, кап 80 совпадений, glob-фильтр;
  - `write_file` — создание/перезапись целиком, ответ `{path, created, changed, diff}`.

**Стрим и события**
- События NDJSON: `delta` (куски финального текста) → `file_change` (после каждой фактической записи) → `done` / `aborted` / `error`.
- Собственный unified-дифф без зависимостей: общий префикс/суффикс строк, один `@@`-hunk с 3 строками контекста; новый файл → `--- /dev/null`; дифф обрезается до 120 строк.

**Безопасность (джейл путей)**
- Все пути строго внутри `WORKSPACE_ROOT` (по умолчанию — корень репозитория): лексическая проверка `path.resolve` + startsWith.
- `realpath`-проверка для существующих файлов: симлинки наружу под запретом; symlink-записи пропускаются при обходе.
- Запрещены на чтение/запись: `.git/`, `node_modules/` и другие джанк-директории, `.env*`, `*.log`, файлы >2MB; бинарные файлы не читаются и не ищутся.
- Защита статики от path traversal (`..`, `\0`, выход за `public/`), лимит тела запроса 200KB.

**UI (`public/`)**
- Тёмный одностраничный чат на vanilla JS: стриминг ответов с курсором, авто-скролл с «прилипанием» к низу.
- Карточки `file_change`: путь, бейдж «создан/изменён», раскрывающийся unified-дифф.
- XSS-safe markdown: код-блоки с кнопкой «Копировать», инлайн-код, жирный, заголовки, списки, ссылки.
- Кнопка остановки генерации (AbortController), чипсы-подсказки сценариев, чип рабочей области из `/api/status`.

### Checked (E2E-сценарии)

- «сгенерируй файл file-assistant/CHANGELOG.md …» → `write_file` → `file_change` с диффом в UI, файл на диске.
