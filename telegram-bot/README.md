# Душевный Telegram-бот (LLM: GPUStack / Ollama)

Стоящий Telegram-бот — чат-собеседник на LLM. Механика провайдеров и моделей повторяет
соседний проект `llm-agent-app`: провайдер `gpustack` (шлюз с Bearer-ключом, фиксированный
каталог моделей) и `ollama` (локальная Ollama без ключа, живое обнаружение моделей).

## Требования

- Node.js 22+ (используются встроенные `fetch` и флаг `--env-file`; проверено на Node 24)
- Токен бота от [@BotFather](https://t.me/BotFather)

## Запуск

```bash
cd telegram-bot
npm install
copy .env.example .env      # Windows (на Linux/macOS: cp .env.example .env)
# заполните .env: TELEGRAM_BOT_TOKEN и LLM_API_KEY (ключ GPUStack)
npm start                   # node --env-file=.env src/bot.js
```

Переменные окружения (см. `.env.example`):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | Токен бота от @BotFather (обязателен) |
| `LLM_PROVIDER` | `gpustack` | Стартовый провайдер: `gpustack` \| `ollama` |
| `LLM_MODEL` | `qwen3.8-27b` | Стартовая модель GPUStack |
| `LLM_BASE_URL` | — | Адрес GPUStack (без `/v1`); обязателен при провайдере `gpustack` |
| `LLM_API_KEY` | — | Bearer-ключ GPUStack; обязателен при провайдере `gpustack` |
| `LLM_OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес локальной Ollama (без ключа) |

Токен и ключи в код не зашиваются — только через `.env`.

## Команды бота

| Команда | Действие |
|---|---|
| `/start`, `/help` | Приветствие и список команд |
| `/provider` | Показать текущего провайдера и доступных (`gpustack`, `ollama`) |
| `/provider gpustack\|ollama` | Сменить провайдера; модель сбрасывается на первую модель нового провайдера (как в `llm-agent-app`) |
| `/model` | Показать текущую модель и нумерованный список моделей текущего провайдера |
| `/model <номер или id>` | Сменить модель (валидация по списку текущего провайдера) |
| `/reset` | Очистить историю текущего чата |

Любое обычное текстовое сообщение уходит в LLM с системным промптом «Ты душевный собеседник.»
Ответ длиннее 4090 символов разбивается на несколько сообщений (по границам строк, где возможно).

## Провайдеры и модели

- **gpustack** — фиксированный каталог из трёх моделей (как в `llm-agent-app`):
  `qwen3.8-27b`, `deepseek-v4-flash`, `glm-5.3-flash`. Запросы идут на
  `POST {LLM_BASE_URL}/v1/chat/completions` с заголовком `Authorization: Bearer`.
- **ollama** — живое обнаружение моделей: `GET {LLM_OLLAMA_BASE_URL}/v1/models`
  (OpenAI-совместимый API, без ключа). Если Ollama недоступна — бот покажет понятную
  ошибку и не даст переключиться.
- При переключении провайдера модель сбрасывается на **первую модель нового провайдера**.
- При старте, если выбранная модель Ollama отсутствует в живом каталоге, бот автоматически переключается на первую доступную.

## Хранение истории

Состояние бота хранится в `data/state.json` (создаётся автоматически, в git не попадает):

- `provider` и `model` — текущий выбор (глобальный на бота);
- `chats` — история по каждому чату: **последние 10 сообщений** на чат
  (константа `HISTORY_LIMIT = 10` в `src/store.js`).

Файл перезаписывается после каждого изменения, поэтому выбранные провайдер/модель и история
переживают перезапуск бота (в отличие от `llm-agent-app`, где провайдер не персистится —
здесь это сделано сознательно и проще). Если файл повреждён, бот стартует с чистого состояния
(провайдер/модель — из `.env`).

## Структура

```
telegram-bot/
├─ package.json       — зависимости (только grammy), скрипт start
├─ .env.example       — пример окружения (токен/ключи — плейсхолдеры)
├─ src/
│  ├─ config.js       — разбор и валидация env, SYSTEM_PROMPT
│  ├─ catalog.js      — каталог GPUStack + живое обнаружение моделей Ollama
│  ├─ llm.js          — вызов /v1/chat/completions (без стриминга, без tools)
│  ├─ store.js        — состояние в data/state.json (провайдер/модель + история чатов)
│  └─ bot.js          — граммY-бот: команды, история, типизация, отправка
└─ data/              — state.json (создаётся в рантайме, игнорируется git)
```
