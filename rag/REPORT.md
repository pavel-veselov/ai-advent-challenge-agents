### Замечания по методике

- Контрольные запросы подобраны после живой проверки: 4 формулировки из исходного плана
  («как работает планировщик» → memory-layers.md, «как добавить MCP-сервер» → CONTRACT.md,
  «как добавить новый инструмент агенту» → ToolRegistry.kt, «как определить координаты по
  названию города» → LocationTool.kt) стабильно попадали в *другие* документы, потому что
  тему в корпусе честно покрывают и другие файлы: «Планировщик» — это раздел CONTRACT.md
  (день 17/18), «добавить MCP-сервер» документируют README mcp/mcp2 и код
  McpServersStore/Controller, а «город пользователя» — раздел README mcp2, дословно
  повторяющий KDoc LocationTool. Заменённые запросы (см. таблицу) адресуют уникальное
  содержание ground-truth файла — иначе hit@k мерил бы не качество retrieval, а
  неоднозначность корпуса.
- Единственный промах (structural, hit@1 по LocationTool.kt): с рейтингом 0.8075 выиграл
  чанк README mcp2 «MCP-2 > Инструмент» (0.7931 у LocationTool) — README почти дословно
  повторяет KDoc кода, поэтому для embedding-модели это фактически дубликат темы.
  В top-3 источник всё равно присутствует (hit@3 = 8/8 у обеих стратегий).
- Search-команда живьём подтверждена на 8+ запросах: scores 0.57–0.83, при поиске без
  `--strategy` обе стратегии конкурируют в одном рейтинге (в top-3 бывают чанки обеих).

## Выводы

- Фиксированные окна выигрывают по совокупному hit@k: перекрытие в 200 символов сохраняет контекст на границах разрезов, а равномерная длина чанков (~≤1000 симв.) делает векторы сопоставимыми по «плотности» смысла.
- **Fixed** — фикс. окна ~1000 симв. с перекрытием 200: равномерное покрытие любого текста (особенно PDF, где нет разметки), простота и предсказуемость; плата — разрезы посреди предложений и потеря структурных границ.
- **Structural** — секции по MD-заголовкам / декларациям кода / страницам PDF: чанки соответствуют смысловым единицам, что особенно полезно для кода (одна функция = один чанк); плата — разброс длин (мелкие секции рядом с крупными) и зависимость от качества разметки документа.
- **Практический trade-off**: для смешанного корпуса (доки + код + PDF) структурная стратегия лучше для структурированных документов (MD, код, постраничные PDF), фиксированная — надёжный универсальный дефолт для «плоского» текста без разметки; их можно комбинировать (structural с дожимом fixed для длинных секций).
- **Масштабирование**: брутфорс-косинус по всем чанкам достаточен для сотен чанков; при росте коллекции до миллионов векторов индекс следует перенести в FAISS (ANN-индексы IVF/HNSW) или аналог векторной БД.
