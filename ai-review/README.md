# AI Code Review

Пайплайн автоматического ревью кода (день 32): на каждый PR запускается GitHub Action, ассистент получает diff и изменённые файлы, ищет релевантный контекст по документации и коду проекта через **RAG**, и публикует текст ревью комментарием в PR.

LLM и эмбеддинги — **GPUStack** (OpenAI-совместимый API), как в `dev-assistant`. Ни одного npm-пакета — только Node 20+ и встроенный `fetch`.

## Как работает

```
GitHub Action (pull_request)
        │  PR_NUMBER + GITHUB_TOKEN
        ▼
ai-review/review.js
        │
        ├─ 1. Diff: GET /repos/:repo/pulls/:n/files (патчи изменённых файлов)
        ├─ 2. RAG: корпус = все *.md/CONTRACT + код проекта (*.js/.ts/.java/.kt/…)
        │        чанки ~900 симв. → эмбеддинги (qwen3-vl-embedding-8b)
        │        запросы = имя файла + первые строки патча → cosine → топ-8 фрагментов
        ├─ 3. LLM: glm-5.3-flash → diff разбит на нумерованные ханки [H1]…[Hn],
        │        каждый ханк проверяется по чек-листу (off-by-one, ошибки, null, границы)
        └─ 4. Комментарий в PR (существующий комментарий бота обновляется — без спама)
```

Формат ревью:

- 🐛 **Потенциальные баги** — ошибки в логике, обработке ошибок, пограничные случаи
- 🏗 **Архитектурные проблемы** — нарушения соглашений проекта, связность, дублирование
- 💡 **Рекомендации** — что улучшить

## Настройка (один раз)

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**, добавьте:

| Секрет | Значение |
|---|---|
| `LLM_BASE_URL` | Базовый URL GPUStack (как в `dev-assistant/.env`) |
| `LLM_API_KEY` | Ключ GPUStack (как в `dev-assistant/.env`) |

2. Модели имеют дефолты (`glm-5.3-flash`, `qwen3-vl-embedding-8b`) — переопределяются секретами `LLM_MODEL` / `EMBED_MODEL`, если нужно.
3. `GITHUB_TOKEN` подставляется Actions автоматически; права заданы в workflow (`pull-requests: write`).

Workflow: `.github/workflows/ai-review.yml` — триггер `pull_request` (`opened`, `synchronize`, `reopened`), таймаут 15 минут.

## Локальный запуск (без GitHub)

```bash
# из корня репо; дифф можно взять где угодно (git diff, git diff --no-index …)
node --env-file=dev-assistant/.env ai-review/review.js --diff путь/к/change.patch
```

Ревью печатается в stdout — так же, как в CI, но без запросов к GitHub API.

## Ограничения

- В промпт попадают максимум 25 файлов и ~40 000 символов diff (бинарные файлы и lock-файлы пропускаются, длинные патчи усекаются).
- RAG-корпус строится на каждом прогоне (без кэша): 250 файлов / ~2000 чанков → ~1-2 минуты на эмбеддингах; полный прогон ~2 минуты.
- Ревью зависит от доступности GPUStack — при ошибке сети шаг падает с понятным сообщением (причина сетевого сбоя логируется из `err.cause`).
- Комментарий бота помечен `<!-- ai-review-bot -->` и обновляется, а не плодит новые.

## Доступность GPUStack с раннера

`gpustack.data.lmru.tech` — внутренний сервис (резолвится в приватный IP `10.x.x.x`), поэтому **GitHub-hosted runner (`ubuntu-latest`) до него не достучается**: DNS не вернёт приватный адрес из интернета, а TLS-сертификат корпоративный. Прогон упадёт на первом запросе к `/v1/embeddings` с `fetch failed`.

Варианты:

1. **Self-hosted runner в корпоративной сети** — правильный путь для внутреннего GPUStack. Заводится в Settings → Actions → Runners → New self-hosted runner (любая машина/VM, где резолвится GPUStack), затем в workflow: `runs-on: self-hosted`. Скрипт больше ничего не требует — переменные и API те же.
2. **Публичный LLM-эндпоинт** — если появится прокси с внешним доступом, достаточно поменять значение секрета `LLM_BASE_URL` (и ключ), workflow менять не нужно.
3. **Локальный режим** — полный прогон ревью без GitHub-раннера (см. выше), он работает из корпоративной сети из коробки.
