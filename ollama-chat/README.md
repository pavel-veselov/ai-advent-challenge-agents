# Ollama Chat

Минималистичный веб-чат для локальной Ollama: тёмный UI, стриминг ответов, один Node-сервер без npm-зависимостей.

## Архитектура

```
браузер → ollama-chat (Node, :8080)
              ↓
      http://127.0.0.1:11434  (Ollama)
```

Ollama работает на ноутбуке (в Docker). frpc на ноутбуке пробрасывает порт 11434
на frps-сервер VPS (proxyBindAddr 127.0.0.1). Поэтому контейнер на VPS
достигает «локальной» Ollama по `127.0.0.1:11434` — отсюда `network_mode: host`
в compose-файле.

Сервер раздаёт статику из `public/` и проксирует `POST /api/chat` на стриминговый
эндпоинт Ollama (NDJSON) через строгую FIFO-очередь: Ollama генерирует
последовательно, поэтому одновременно активен ровно один запрос к модели,
остальные ждут. Состояние очереди: `GET /api/queue`.

## Локальный запуск

```bash
node server.js
# или
npm start
```

Переменные окружения:

| Переменная       | По умолчанию            | Назначение                                        |
|------------------|-------------------------|---------------------------------------------------|
| `PORT`           | `8080`                  | Порт, на котором слушать                          |
| `OLLAMA_URL`     | `http://127.0.0.1:11434`| Адрес Ollama                                      |
| `MODEL`          | `qwen2.5-coder:3b`      | Модель                                            |
| `MAX_MESSAGES`   | `10`                    | Сколько последних сообщений отправлять модели    |
| `MAX_BODY_BYTES` | `1000000`               | Максимальный размер тела `POST /api/chat`         |

## Деплой на VPS

```bash
scp -r ollama-chat user@VPS_IP:~/ollama-chat
ssh user@VPS_IP
cd ~/ollama-chat
sudo docker compose up -d --build
```

Если плагин `docker compose` не установлен:

```bash
sudo docker build -t ollama-chat .
sudo docker run -d --name ollama-chat --restart unless-stopped --network host ollama-chat
```

Дальше открывается `http://VPS_IP:8080`.

Проверка: `curl http://VPS_IP:8080/api/health` — должен вернуть
`{"status":"ok","model":"qwen2.5-coder:3b","ollamaUp":true,...}`.

## Ограничения

- Работает, пока включён ноутбук с Ollama и frpc. Ноутбук выключен → health
  отчитывается `degraded`, в чате появляется «Ollama недоступна (ноутбук выключен?)».
- История не хранится: она живёт в памяти вкладки и сбрасывается при обновлении.
- Запросы идут в очереди: при нескольких пользователях ответы генерируются по одному.
- Аутентификации нет: кто имеет доступ к порту, тот и чатится с моделью.
- `qwen2.5-coder:3b` — дефолтная модель (быстрая на CPU); поменять через `MODEL`.
